# 对话整理为笔记/日记

把当前对话沉淀为一篇笔记或日记，连同对话中出现的图片一起上传到 Terra 平台。

平台操作（预检、查重、分类、发布、图片上传、回报）一律遵循 **wiki-ops** 技能的约定；若尚未加载，先通过 Skill 工具加载 `wiki-ops`。

## Instructions

1. **判定模式**。根据用户表述与对话性质二选一（用户明说时以用户为准）：
   - **日记**：第一人称、带当天日期、记录经历/过程/感受。标题格式 `YYYY-MM-DD 主题`（如 `2026-10-31 折腾 Terra 插件`）。
   - **笔记**：知识性总结，第三人称视角，标题即主题。用户说"记个笔记"、"整理成笔记"或对话偏技术内容时默认此项。
   拿不准时直接问用户一句。

2. **整理正文**（Markdown）：
   - **笔记**：`背景 → 要点（分节）→ 决策与结论 → 遗留问题`；信息密度优先，删掉寒暄与过程性废话。
   - **日记**：`今天做了什么 → 遇到什么 → 怎么解决/什么感受 → 明天想做什么`；保留第一人称与关键细节，重要对话原话可用引用块保留。
   - 两种模式都不要凭空补充对话中不存在的结论。

3. **处理图片**。收集对话中出现的图片（用户贴的本地文件、Agent 生成的可视化产物）：
   - 按 wiki-ops 的「图片上传管线」逐张 `upload_image`，把返回 URL 以 `![描述](URL)` 嵌入正文对应语义位置。
   - 生成类可视化若只有源码没有图片文件，先渲染导出 PNG 再上传。
   - 取不回原图的，留 `> [图片待补：…]` 占位并告知用户。

4. **展示草稿并确认**。完整正文（含嵌入后的图片）展示给用户，根据反馈修订。

5. **上传**（遵循 wiki-ops 管线）：
   - 查重：同日同主题的日记/笔记已存在时按「查重与更新」处理（日记通常另建新篇，除非用户要合并）
   - 智能分类：日记优先挂"日记"相关的现有叶子分类，笔记按主题挂分类；没有合适分类时按 wiki-ops 约定提议新建
   - 询问用户「草稿还是发布」
   - `create_post`：`title` = 步骤 1 确定的标题，`slug` = kebab-case 英文（日记用日期开头，如 `2026-10-31-terra-plugin`），`bodyMd` = 整理后的正文，`summary` = 一句话，`tags` = `日记` 或 `笔记` + 主题标签

6. **回报**：文章 ID、标题、分类路径、状态、已上传图片数量及占位提醒。
