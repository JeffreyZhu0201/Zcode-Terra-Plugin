# terra-wiki 插件自诊断

按顺序执行检查，每一步给出结论与下一步动作，最后输出一张诊断总表。不要跳步：前面的结论会决定后面怎么查。

## 检查 1 · 插件是否安装并启用

本技能就是插件的一部分——**你能读到这份 SKILL.md 并执行 /wiki-doctor，说明插件已安装且已启用**。直接在结论表记 PASS，进入检查 2。

若用户是在别的会话里说"技能不存在"，让 TA 到 **设置 → 插件管理 → 已安装** 标签确认 terra-wiki 行的开关是开着的；如果列表里没有，回 **发现** 标签从市场 `zcode-terra-plugin` 安装。

## 检查 2 · MCP 连通性（核心检查）

通过插件的 terra-wiki MCP 调用 `list_categories`（只读），按结果分流：

| 结果 | 诊断 | 下一步动作（如实转告用户） |
| --- | --- | --- |
| ✅ 返回分类列表 | 配置与凭据全部正常 | 输出诊断总表：配置 OK、Token OK、可见分类 N 个（列出 name），结束 |
| 🔒 401 / 403 / 未授权 | 服务地址对，但 **api_token 缺失或无效** | 指导填写 Token（见下方「配置入口」），确认在 Terra 后台签发且未过期 |
| 🔌 连接被拒 / 超时 | **server_url 不对或 Terra 未启动** | 确认 Terra 是否在运行（默认 `http://localhost:3000`）；若部署在别的地址/端口，改 server_url |
| 🧩 找不到 terra-wiki 工具 | 插件未启用或本次会话早于安装 | 让用户**重启会话**（新任务的 capability 目录在安装时快照） |

## 检查 3 · 配置入口（仅在检查 2 失败时转告）

**配置区不在插件市场（发现）页**——市场卡片上没有配置入口，这是最常见的困惑。准确路径：

1. **设置 → 插件管理 → 已安装** 标签
2. 找到 **terra-wiki** 行，点进**详情**
3. 展开底部 **高级信息** → **配置** 区
4. 填 `Terra API Token`（`server_url` 用默认值即可，除非 Terra 不在本机 3000 端口）
5. 点 **保存配置**
6. **新建会话**后重跑 `/wiki-doctor` 验证（MCP 连接随插件启停，改配置要新会话才生效）

注意：`api_token` 故意没有标记 sensitive——sensitive 字段当前无法在界面填写（ZCode 尚未提供安全存储 UI），属官方已知限制。

## 输出格式

```
🩺 terra-wiki 自诊断
1. 插件安装/启用 …… ✅
2. MCP 连通性    …… ❌ 401 未授权
3. 建议          …… 设置 → 插件管理 → 已安装 → terra-wiki 详情 → 高级信息 → 配置 → 填 Token → 保存配置 → 新会话重试
```

全部通过时额外列出可见分类树，并提示可以直接开始用 `/distill-skill`、`/distill-rules`、`/conversation-notes`。
