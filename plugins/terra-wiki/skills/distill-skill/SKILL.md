# 对话蒸馏为通用 Skill 文档

把对话中验证过的做法提炼成一份**脱离本对话也能用**的通用 Skill 文档，上传到 Terra 平台沉淀。

平台操作（预检、查重、分类、发布、回报）一律遵循 **wiki-ops** 技能的约定；若尚未加载，先通过 Skill 工具加载 `wiki-ops`。

## Instructions

1. **识别可复用内容**。通读当前对话，找出满足以下条件的部分：
   - 解决了一类问题（而非一次性操作）
   - 有明确步骤、决策点或踩坑教训
   - 换个上下文依然成立

   如果对话里没有可沉淀的方法论，如实说明并询问用户想沉淀哪个片段，不要硬凑。

2. **撰写通用 SKILL.md 文档**。产出一份完整的 SKILL.md 格式文档：
   - YAML frontmatter：`name`（kebab-case 英文短名）与 `description`（一句话说明何时使用，写给未来的 Agent 或读者看）
   - 正文结构：**适用时机 → 前置条件 → 操作步骤（祈使句、按序编号）→ 陷阱与注意 → 验证方式**
   - **去个性化**：删掉"你刚才"、"如图所示"等对话性表述；具体文件路径、仓库名、密钥等替换为泛化占位符（如 `<你的仓库>`）
   - **自包含**：不依赖本对话的任何上下文即可执行

3. **展示草稿并确认**。把完整文档展示给用户，根据反馈修订。

4. **上传**（遵循 wiki-ops 管线）：
   - 查重：同名或同主题文章已存在时按 wiki-ops 的「查重与更新」处理
   - 智能分类：优先挂到与"技能/方法沉淀"相关的现有叶子分类；没有合适分类时按 wiki-ops 约定提议新建
   - 询问用户「草稿还是发布」
   - `create_post`：`title` = 技能名，`slug` = frontmatter 的 name，`bodyMd` = SKILL.md 文档**原文（含 frontmatter）**，`summary` = description 一句话，`tags` = 2–5 个主题标签（含 `skill蒸馏`）

5. **回报**：文章 ID、标题、分类路径、状态（草稿/已发布），并提醒"正文即 SKILL.md 原文，日后可直接复制复用"。
